# NFG Crash — Fix offline arcade points stuck as "pending sync" (Windows PC)

Paste this entire prompt into **Cursor on your Windows PC** that runs the live server at **https://y666suf.com**.

## Problem

iOS users earn arcade points offline (NFG Jump milestones, NFG Rush, NFG Blocks level clears). When the server comes back online, the app shows **"X pts pending sync"** forever because:

1. The app was replaying `milestone` / `level_clear` actions, which **require an active game session** on the server → sync fails with `no_session`.
2. The app only tried to flush when opening a specific game — not globally on connect.

## Fix (Mac already pushed to GitHub `main`)

### Server: new `offline_sync` action

`server/mobile-arcade.js` now supports:

```
POST /api/mobile/arcade/play
{
  "gameId": "nfg_snake_jump" | "nfg_vault_run" | "nfg_blocks",
  "action": "offline_sync",
  "payload": {
    "queueId": "<uuid from iOS>",
    "points": 3000,
    "originalAction": "milestone",
    "height": 2500,
    "distance": 400,
    "level": 3
  }
}
```

Behavior:
- Credits `points` to the user's wallet (idempotent — same `queueId` never pays twice)
- Updates best height / distance / level from payload
- Works **without** an active run session

Helper: `applyOfflineArcadeSync()` in `mobile-arcade.js`

### iOS (separate TestFlight build)

- Flushes offline queue on connect + every 30s while online
- Uses `offline_sync` instead of replaying milestone/level_clear
- Migrates offline queue when guest links TikTok

## Troubleshooting

| Symptom | Cause | Fix |
|---------|-------|-----|
| `invalid_action` on offline_sync | Old mobile-arcade.js | Pull + restart |
| `invalid_sync` | Missing queueId or points | iOS sends both — check auth token |
| Points still pending on iOS after server fix | Old iOS build | Ship new TestFlight with flush timer |
| 401 on curl | Bad/expired token | Use fresh token from app |
| gained is 0 but ok true | Duplicate queueId already synced | Normal — idempotent |
