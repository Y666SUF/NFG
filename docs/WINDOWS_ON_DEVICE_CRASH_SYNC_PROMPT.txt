## Step 3 — What the new endpoints do (do not “simplify” them away)

### `POST /api/mobile/crash/solo/sync` (`server/mobile-crash-solo.js`)

- Auth: Bearer session (`validateBearer`)
- Body: `{ rounds: [ { id, stake, result, netDelta, tax, crashPoint, settleMult?, payout?, roundId? } ] }`
- `result` is `"win"` or `"lose"`
- Idempotent via `profile.syncedCrashSoloIds[id]`
- Applies `pointStore.add(user, netDelta, { countAsEarned: netDelta > 0 })`
- Optional tax → `pointStore.addTaxToPot(tax)` when present
- Caps: drop abusive rows (`stake` / `|netDelta|` > 50_000_000) but mark id synced so the client queue unblocks
- Response: `{ ok, applied, remaining, wallet }`

### `POST /api/mobile/inventory/sync` (`server/mobile-inventory.js`)

- Auth: Bearer session
- Body: `{ spends: [ { id, kind, count, target? } ] }`
- `kind`: `steal` | `shield_break` | `jet_lock` (and aliases)
- Steal **with** `target` → `game._trySteal` (charge burns only on success); retryable failures stay in `remaining`
- Bare charge burns (no target) → `consumePowerupCharge` idempotent via `syncedInventorySpendIds`
- Response: `{ ok, applied, remaining, results, wallet }`
