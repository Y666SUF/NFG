## Step 2 — Critical file: `server/mobile-auth.js`

### A. Durable device → TikTok bindings (survives server restart)

State file `data/mobile-sessions.json` now includes **`deviceLinks`**:

```json
{
  "pendingLinks": { ... },
  "sessions": { ... },
  "deviceLinks": {
    "<device-uuid>": {
      "userId": "tiktokusername",
      "displayName": "Display Name",
      "linkedAt": 1710000000000,
      "linkedVia": "tiktok"
    }
  }
}
```

On **successful !link** (`completeLinkFromTikTok`), call `saveDeviceLink(deviceId, userId, displayName)`.

On **explicit unlink only** (logout with `unlink: true`), call `clearDeviceLink(deviceId)`.

### B. Restore TikTok session on bootstrap (no re-link after restart)

`POST /api/mobile/auth/app-guest` must:

1. Return existing valid session for device (prefer `linkedVia: tiktok` over guest).
2. If no session but **`deviceLinks[deviceId]`** exists → issue **new TikTok token** (`restored: true`), NOT a new guest.
3. Accept optional body field **`claimUserId`** — if it matches the stored binding, restore that TikTok user.

Only create a **new app guest** when there is no session AND no device link.

### C. Session TTL + sliding renewal

- `SESSION_TTL_MS` = **365 days**
- In `validateBearer`, on each valid request: `session.expiresAt = now + SESSION_TTL_MS`

### D. One session per device on link / new guest

- `clearDeviceSessions(deviceId)` before creating TikTok session after link.
- `findValidSessionForDevice` prefers TikTok over guest.

### E. Logout semantics

`POST /api/mobile/session/logout` body:

```json
{ "deviceId": "...", "unlink": true }
```

- Always clears all **sessions** for that device.
- Clears **`deviceLinks[deviceId]`** only when `unlink: true` (Settings → Unlink).
- Normal token expiry / app updates must **NOT** send `unlink: true`.

### F. Migration on server start

`migrateDeviceLinksFromSessions()` backfills `deviceLinks` from existing TikTok sessions and completed `pendingLinks` with `status: "linked"`.
